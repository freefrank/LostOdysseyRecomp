# 0.6.0 prerelease audit repairs

Baseline: `9a1617af1b05dae5ea3d317f6479b8d3c467e4d0` (`v0.5.20`).
The original audit was run on `0.6.0-prerelease`; its statement that `main`,
the release tag and published assets were unchanged applies to that historical
baseline. The follow-up repairs below are unreleased changes on `main`.

## Follow-up repairs — 2026-09-18

The attached review identified four runtime/tool findings and three updater
follow-ups. The main-source repairs below have not been validated with a full
game, real release package, or Steam Deck run.

| Finding | Current repair and evidence |
| --- | --- |
| F1 — sampled cache equality | Vertex and index cache hits now compare the complete source byte content. Focused Clang `-O2` fixtures passed 3,668,947 vertex-cache checks, 16,809,648 geometry checks and 16,438 prerelease geometry checks, including mutations in the former sampled blind spot. No runtime GPU or frame-time result is claimed. |
| F4 — index cache memory pressure | `IndexCache` now counts source snapshot and converted-index vector capacity against a 64 MiB payload budget, evicts under byte or entry pressure, and bypasses oversized entries. Renderer diagnostics expose current and peak bytes plus evictions. The earlier 15 W sampled-match performance numbers are not reused after this correctness repair; final-binary performance remains to be measured. |
| F2 — benchmark save safety | `tools/drive_city.py --dry-run` returns before filesystem writes, rejects overlapping source/target save paths, and stages an existing run save while retaining a backup and rolling back on copy, launch or replacement failure. Five focused cases passed. This validates the tool fixture, not ordinary in-game saves. |
| F3 — pause-aware PPC timebase | `mftb` and the kernel timestamp bundle now derive from the same pause-aware nanosecond clock. An independent WSL C++ pause test passed; exploration, battle and cutscene runtime regression remains open. |
| U1/U2 — Linux apply cleanup and launch failure | Successful POSIX apply removes completed archive/stage data; direct `execv` failure restores the previous AppImage when available. Isolated production apply fixtures passed success cleanup and failure rollback. No real AppImage or Steam/Gamescope update run was performed. |
| U3 — standalone Windows recovery | Standalone recovery now uses the helper itself as the runner source, so it does not depend on a missing or damaged main executable. This path was source reviewed; no real Windows package transaction was run. |

These results supersede the earlier F1 row below that described sampled
comparison as a passing repair. The historical audit and its original limits
remain preserved for provenance.

## Verified results

- Linux native suite with Clang ASan/UBSan: 48 PASS, 0 FAIL, 2 explicitly SKIPPED. The skipped `polygon_offset` and `bloom_prefilter` tests require real DXC/GPU and are not CPU fixtures.

The runtime source in that build is commit `71b6c8f`; later commits change only CI, one legacy test fixture, and documentation. This was translation-unit compilation, not a full runtime link.

## CI issues discovered and corrected

Native validation exposed three fixture/setup issues: missing `X11/Xlib.h`, a legacy `ConsentEpoch` definition missing the production `noexcept` specification, and the absence of the runtime Plume interface patch in the standalone CI checkout. All three were corrected without skipping the fixture. The previously failing `temporal_collection_nonblocking` fixture now passes with 100 safe skips, zero allocations, zero consent calls and zero submissions when the sampler is unprepared.

The earlier production-build run has a failed Linux job because its post-compilation test step encountered the old fixture signature. Its compilation step passed. Do not interpret that entire earlier job as green; the subsequent corrected native workflow above passed on both platforms.

## Reproduction

Initialize submodules and install the Plume X11 platform headers (`libx11-dev` on Ubuntu), then run:

```sh
git -C thirdparty/plume apply --reverse --check ../../tools/patches/plume-lostodyssey.patch >/dev/null 2>&1 || git -C thirdparty/plume apply ../../tools/patches/plume-lostodyssey.patch
# Historical audit command; native_audit.py has since been removed.
python3 tools/tests/native_audit.py --cxx clang++ --sanitize --out out/audit/native
python3 tools/tests/menu_boundary_regression.py --cxx clang++ --sanitize --out out/audit/menu
python3 tools/tests/shader_prebuild_regression.py --cxx clang++ --sanitize --out out/audit/prebuild
python3 tools/tests/kernel_lifetime_regression.py --cxx clang++ --sanitize --out out/audit/lifetime
python3 tools/tests/presentation_failure_regression.py --cxx clang++ --sanitize --out out/audit/presentation
cmake -S tools/shader_pack -B out/audit/pack -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build out/audit/pack --target LoShaderPackTool LoPortableShaderPackTest LoPortableShaderPackIntegrationTest LoPortableShaderContractTest
ctest --test-dir out/audit/pack --output-on-failure
```

Source repairs: `71b6c8f6c3ea0ef073d749e7a1ff5cc62fc11fb6`.
Permanent release/test wiring: `bdb0b8224ee129cf1bb917e96835c4a7339685c4`.
CI/legacy fixture corrections: `e705940`, `8336e9d`, `baf5a90`.

The one-off source-transfer/build workflow was removed after use. The permanent native workflow has read-only repository permissions.

## Validation limits

CPU fixtures and extracted routines are not full-game execution. No full runtime link, real GPU recovery, complete playthrough, ARM runtime, or Steam Deck 15 W / 720p60 certification is asserted here.

Exact vertex comparison trades additional CPU memory reads/storage for correctness. Its effect on frame time requires measurement. Real occlusion queries and additional Steam Deck performance work remain separate tasks; this patch does not claim to implement them.
