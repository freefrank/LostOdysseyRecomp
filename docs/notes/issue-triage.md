A [real public `@codex` reply](https://github.com/freefrank/LostOdysseyRecomp/issues/21#issuecomment-5669773986) was subsequently verified; the earlier pending-observation statement no longer applies.

The repository contains a bounded, non-agentic workflow for preliminary analysis of newly opened GitHub Issues. `.github/workflows/issue-triage.yml` runs on `issues.opened` and also supports manual `workflow_dispatch` with the required `issue_number` input, a `dry_run` input that defaults to `true`, and an optional `comment_id` for previewing an existing mention. The workflow also handles a new human `@codex` request in an Issue comment when the author is an OWNER, MEMBER or COLLABORATOR; pull requests are excluded, while a closed Issue may still receive a manually requested analysis. Each new qualifying mention is analyzed by comment ID, so an earlier automated triage marker does not block a later request. The job runs on GitHub-hosted Ubuntu and invokes `tools/issue_triage/triage.py`; it does not execute issue text, model output, commands or attachments.

To request a follow-up analysis, an authorized collaborator can comment, for example: `@codex Please analyze this issue against the codebase and list the relevant files, likely causes and the next verification step.` The workflow reads the issue, recent human discussion (up to 12 comments), and ranked first-party Git-tracked code snippets (up to 6 snippets and 24,000 characters) for read-only model context. It replies as `github-actions[bot]`; this is a repository workflow and does not use the official Codex App comment identity.

Since 2026-10-07 the analysis is written by Claude through the Claude Code CLI (`claude -p`), authenticated with the repository secret `CLAUDE_CODE_OAUTH_TOKEN` that the Claude GitHub App created, so it counts against the Claude subscription. The CLI runs with no tools (`--tools ""`), in `--safe-mode` (no CLAUDE.md, hooks, MCP servers or skills) and from an empty temporary directory; GitHub reads and writes stay in `triage.py`. Repository variables can override `ISSUE_TRIAGE_MODEL` and `ISSUE_TRIAGE_EFFORT`; the defaults are `claude-sonnet-5-5` and `medium`. Before that date the workflow called a `chat/completions` gateway with `ISSUE_TRIAGE_API_KEY` and `gpt-5.6-luna`. Issues created by the Discord sync are triaged through `workflow_dispatch`. It limits repository context and model output, rejects redirects, screens the generated comment for credentials and `@` mentions, and uses the marker `<!-- lost-odyssey-issue-triage:v1 -->` to avoid duplicate bot comments. Manual dry runs write a local `issue-triage-preview.md` preview and do not post to GitHub.

The repository secret `ISSUE_TRIAGE_API_KEY` and optional variables `ISSUE_TRIAGE_BASE_URL` and `ISSUE_TRIAGE_MODEL` configure the deployed workflow.
