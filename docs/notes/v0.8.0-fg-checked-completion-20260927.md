# v0.8.0 FG checked completion：第一批实现

基线：`88b1a4b5bff98315aec8eb49f2cb3eb7527711e3`。对应交接中的P0-01/P0-03、P1保护和P4-01/P4-03的部分代码工作，不改变里程碑定义或验收状态。

## 已实现

游戏路径新增一个只记录post-present queue marker的提交/完成serial的轻量记录器。只在`vkQueueSubmit`成功后发布serial；只有匹配serial的`vkWaitForFences`成功才回收snapshot和DepthRemapper输入。失败提交、旧serial、重复完成和pending状态下的覆盖不能产生复用资格。此记录器不包含standalone probe的explicit SDK timeline模式。

`Session::Presented`对accepted Present先提交completion marker，再查询SDK状态。`GetState`失败不再绕过marker进入device-idle释放路径。`Quiesce`、resize调用边界和`Shutdown`统一先执行checked input drain；`Disable`失败以及有未决FG输入的rejected Present走明确的非零退出路径。记录/标记后缺少Present完成证据的输入不得被下一次Prepare覆盖，也不能凭device-idle释放。

`CompleteForFrameGeneration`独立检查FG的depth/motion元数据：当前帧/epoch、相机标记、深度约定、完整且匹配的零偏移区域，以及Tracked或ResetInitialization运动状态。运行时保留两张纹理，不重新要求已在producer侧验证且没有复制的color/invalidity。Composite入口及Session均使用此FG资格检查；Hybrid不再从composite路径混入FG。投影数学和原有producer/lease身份检查仍负责其各自的完整契约，元数据通过不代表实际画质或显示通过。

Composite消费端接受匹配的DLSS或FSR SR provider/consumer，不篡改原FramePlan。`CompleteForConsumer`、FSR质量档位、NativeAA、SR token和SrFailureAction原语义保持不变。FG历史在输出/输入尺寸、格式、backbuffer数量、provider变化或ResetInitialization时局部reset。

## 证据与限制

本地使用C++20、`-Wall -Wextra -Werror -pedantic`构建并运行completion-only定向测试：22项检查通过。该结果不覆盖SDK、Vulkan执行、完整Session编译、真实窗口或显示器。

新增`streamline_game_session_contract`同时覆盖completion记录器、独立FG输入资格和P1的Hybrid SR边界；复用原`temporal_frame_inputs_test.cpp`作为`streamline_sr_inputs_regression`。`FG CPU contracts`工作流在Linux/Windows运行GPU-free测试；实际CI结果以对应commit的运行记录为准。

在 `03b5b117` 第一批实现的初始验证中，未执行真实游戏、GPU validation、SDK sample重跑或显示取证；未访问/修改原始settings、save、profile或shader cache。GamingRig在本轮查询时离线。后续本地补充验证见下文。

## 2026-09-27 本地验证补充

在 `trail/fg-checked-validation-20260927` 上完成 Windows Vulkan RelWithDebInfo 增量构建；受影响的 `streamline_game_session_contract` CPU 契约测试为 `1/1`、52 checks 通过。此前该提交已有 Windows/Linux GPU-free CI 各 `4/4` 通过，本轮复用其结果，没有重复执行完整 CI。

诊断日志发现游戏路径从 `swap->textures.front().imageFormat` 读取到 `VK_FORMAT_UNDEFINED`（值为 `0`），使新增的 FG 格式检查拒绝所有输入。现改用成功创建的 swapchain `createInfo.imageFormat`，并保留格式检查。该修复已包含在本地验证构建中。

当前验证基于 `03b5b117` 加本地后续修复；后续修复允许同帧元数据完整的 `Hybrid` 输入进入 FG 资格检查，以满足尽可能连续启用的目标。这不改变原始 SR 的 FG plan 限制，也不把 Hybrid 标签当作动态对象逐像素正确性的证明。

`out/fg-checked-validation-20260927/run05-format-hidden` 使用 Tracked 输入和显式 Vulkan synchronization validation layer。运行约 43 秒时 FG 已启用，50.92 秒触发隐藏窗口尺寸变化并完成 `825/825` drain，52.309 秒恢复启用；后台运行记录的 actual generated frames 为 `0`。进程以 `0xC0000409` 退出，WER 只有报告、没有 dump，当前不能把退出原因归因到 FG、validation layer 或窗口恢复。validation 日志包含 `PRESENT_AFTER_WRITE`（达到10条后已抑制）以及 imageView、framebuffer width/height 和 topology 错误，因此该运行不是 validation-clean，也不能作为 Gate 1 通过证据。

`out/fg-checked-validation-20260927/run06-hybrid-foreground` 是按用户授权进行的前台静音验证：默认 Hybrid，70秒，foreground window-focus 为 true，SDK errors 0；21.783秒进入 on，直到70.523秒结束没有 off。`validation-summary.json`记录48个 enabled 周期样本全部 `actual_presents=2`，没有 enabled 但未生成的周期样本。最后周期样本记录 `frame=3840`、`source=3839`、`enabled=true`、`accepted=true`、`actual_presents=2`、`generated_intervals=2830`、`total_presents=6670`，host present 最终为3871。进程以0退出，close_requested=true、forced_stop=false，baseline preserved。`scene_2806.png`为host源图，不能证明插帧画面无artifact。由于该运行未加载validation layer，run05的错误仍阻止Gate 1通过。

`run07-no-fg-layer` 使用同一最新 binary，在 `-DisableFg`、后台、12秒、同步 validation layer 开启的条件下退出0并保留 baseline；layer 加载已确认。该 FG-off 对照的 `validation.log` 同样报告 `PRESENT_AFTER_WRITE`，因此这类错误并非 FG 生成独有，但根因尚未定位，也不能据此解除 P0 同步阻断。

游戏的 SDL_QUIT 关闭路径直接 `_Exit(0)`，绕过 `Session::Shutdown`；因此这些运行的 exit 0 只证明驱动和进程结束，不能称为完整 Session 清理通过。

## 复现

```sh
cmake -S tools/tests/streamline_fg -B build/fg-contracts -DLO_STREAMLINE_FG_CPU_ONLY=ON
cmake --build build/fg-contracts --config Release
ctest --test-dir build/fg-contracts -C Release --output-on-failure
```

完成真实V0/V2验证时，应检查`submitted_input_serial`与`completed_input_serial`、retained/pending状态、事件顺序和退出码。`cleanup=complete`只表示Session本地输入清理，不能替代后续Streamline runtime/NGX清理、validation或显示侧证据。SDK内部问题继续复用原有sample归因材料。
