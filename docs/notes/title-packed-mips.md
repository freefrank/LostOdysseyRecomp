# 标题动态背景恢复（2026-09-04）

## 现象与定位

标题 logo 和网点覆盖层可见，背景长期纯黑。Xenia 及用户提供的标题截图中，背景是流动的灰色云雾。

`out/title-background-before/` 第 619 帧的背景 draw 使用 VS `81217dc973d5dc31`、PS `cd6adb98ab83bf90`。临时将该 draw 输出设为品红后，整个背景区域被覆盖，排除了几何未提交或被裁剪的问题。

背景着色器采样两张 256×256 噪声贴图，以及 4×4 BC1 白色乘数贴图和 4×64 BC3 渐变贴图。后两者使用 packed mip 布局；即使是 level 0，短边不超过 16 时也可能位于打包尾部。旧上传路径总从块坐标 (0,0) 解码，把白色乘数读成了黑色。

读取客体内存确认：BC1 白色贴图基址处为零，有效白色块位于字节偏移 256，对应块坐标 (4,0) 的 tiled 地址。

## 实现

对照 Xenia `texture_util.cc::GetPackedMipOffset`，新增 `gpu/texture_layout.h`。读取 fetch word 5 的 packed_mips 位，并在计算 tiled/linear 地址之前加入块坐标偏移。纹理缓存键包含打包标志、实际源地址和选择的 mip，失效检查覆盖打包区域。

这次没有修改背景 shader、曝光或颜色常量。3D 打包布局与完整 mip 链上传仍不属于已实现范围。

## 验证

- Windows runtime 构建通过。
- `LoTextureLayoutTest` 的 14 个布局用例通过，覆盖微小 BC 纹理、长条纹理、普通大纹理及后续 packed mip。
- `out/title-background-fixed/shot_300.png` 恢复灰色云雾及网点，与 Xenia 标题参照的内容一致；未要求不同动画时刻逐像素相等。
- 第 300、600 帧不含 logo 的区域 (0,420)-(1280,620)，RGB 平均绝对变化约为 (12.66,13.22,14.79)，确认背景持续变化。
- 新 runtime 回归 `out/title-packed-regression/`：第 2700 帧首场战斗角色、目标光圈可见，第 4800 帧战后坦克演出正常，白屏没有复发。使用 draw 转换模式，与当前默认一致；自动输入时序导致镜头相位不同。
- 原始截图、纹理数据与诊断输出只保留在 ignored 的 `out/`。

## 独立待查：火焰受击

用户确认 Xenia 的主角火焰受击也存在 glitch。因此不能把 Xenia 的这项异常作为移植版正确输出目标，不能以两边相同证明修复。后续需结合实际 draw/纹理/混合数据，或原机同场景参考定位。本次标题修复不代表火焰受击已修复。
