# v0.8.0 P0退出清理与P4组合连续性：代码补齐

日期：2026-09-27。开发基线为`fix/p0-shutdown-p4-continuity-20260927`的`3b516263`（其父提交为`main`的`81fe3048`）。对应[开发交接](v0.8.0-p0-p1-p4-development.zh-CN.md)的P0-01/P0-03、P1保护、P4-01/P4-03。本文记录实现与验证边界，Gate 1保持**NOT PASSED**，没有发布或全程稳定验收。

## P0：先解决生命周期边界

### 未提交输入取消

`HostInputUse`区分命令记录、原生提交尝试和成功提交serial。`SubmitStart`先标记不可逆的提交尝试；`HostSubmitted`仅接受成功且非零的提交serial。返回错误或提交结果不明时安全终止，不把该资源重新归类为“未提交”。成功提交后的输入仍由既有post-present queue marker及其实际成功的fence wait回收。

GPU呈现入口的退出guard现在调用`Session::CancelUnsubmitted`。只有确认从未尝试提交，才依次执行：原生command buffer reset、撤销该帧SDK输入标签、检查同一queue上的producer copy完成。任何步骤失败均保留资源并非零退出。全部成功后释放snapshot和该次depth remap的资源；未执行的depth资源不进入复用池，避免沿用仅在CPU记录阶段变更过的layout状态。这里的queue-idle只证明producer copy完成，不能代替已提交FG输入的SDK completion。

输入失效导致on→off时清空当前帧depth/motion/UI标签。该行为不按暂停、电影或关卡类别强制关闭FG；只处理已不满足输入合同的状态。正常成功帧仍使用原有队列与semaphore顺序，不新增每帧queue-idle或全资源扫描。

### 退出清理与失败传播

SDL关闭窗口和设置重启成功后的旧`_Exit(0)`路径改为发布退出请求，停止命令处理，跳过尚未完成的shader preparation。窗口线程只发请求；GPU owner在呈现调用栈和取消guard退出后清理。窗口变更handshake尚未完成时也先处理SDL_QUIT，避免退出事件被该handshake挡住。

`Session::Shutdown`先完成checked drain/quiesce，再释放DLSS-G feature；此时Streamline与native NGX session及device仍存活。Vulkan NGX的ReleaseFeature、DestroyParameters及Shutdown1错误现在和D3D12一样保留未释放状态，避免错误返回后清空句柄。video检查SR所有权清理结果和Streamline runtime shutdown，失败时非零退出，成功时才输出`owner shutdown complete ... exit_code=0`。

上述日志是host清理路径的结果，不证明validation-clean、生成帧显示或SDK内部hazard消失。其他主动终止入口和强制结束进程不属于本次SDL关闭/设置重启路径的覆盖范围。

## P4：组合接线与必要边界恢复

renderer的SR后snapshot生产及最终resolve两处准入共用`CompositePlanSupported`，接受匹配的DLSS SR和FSR SR provider/consumer。DLSS Quality、DLAA以及FSR质量档位仍沿用各自SR计划；FG不改写FSR输入、输出尺寸、jitter/reset、SrUseToken或SrFailureAction。没有新增独立FSR FG或D3D12 FG。

Vulkan设备配置阶段用实际选中的physical device检查DLSS-G、Reflex和PCL支持状态。明确不支持时，不加入FG设备扩展或安装FG设备/WSI hooks，继续native SR设备路径。renderer只在游戏FG session实际可用时启用composited snapshot，避免仅凭环境变量在不可用设备上持续复制FG输入。初始化、设备创建或同步失败仍可能沿现有错误路径终止；本次没有把全部SDK错误转为无条件恢复。

FG自己的history增加device epoch、geometry epoch、request signature、有效provider质量及输出region比较；普通cpuSerial变化和无关provider的保存质量不会触发reset。有效输入跨场景仍可连续开启，失效或资源边界后下一次合格输入自动恢复并局部reset。UI分离继续暂挂：`UI=Unavailable`、`provider_ready=false`保持不变。

`DLSS FG continuity`日志提供samples、enabled_samples、enabled_percent、longest_interruption_ms、resumes、reset_samples及reason。计数范围明确为`prepare_attempts_not_display`，包含启动阶段；资源边界可以延长中断时间，但不凭空增加呈现帧样本。它不能独立证明实际生成帧、显示FPS或全游戏连续性。
