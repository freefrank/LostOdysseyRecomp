# 画质增强选项的开销：v0.9.22，RTX 5080，2026-10-10

[English](graphics-options-cost-2026-10-10.md)

本记录给出每个画质增强选项相对"原版"设置多出的毫秒数。每行只改一个设置，其余保持原版。

## 条件

- 版本：v0.9.22 Windows 发布包（`d3888a0d`），Direct3D 12。
- 主机：Windows 11 Pro（10.0.28000），AMD Ryzen 7 9800X3D，NVIDIA GeForce RTX 5080，驱动 616.56。
- 显示：游戏前台运行，无边框全屏 3840x2160。显示器是 144 Hz，Windows 里开着 HDR。HDR 那一行以外，游戏输出 SDR。
- 显卡选择：机器里还插着一块 RX 9070 XT（没接显示器）。`gpu_device` 留空时 v0.9.22 选了 RX 9070 XT，所以测试设成 `NVIDIA GeForce RTX 5080`。每次运行的日志 `video device:` 都确认是 RTX 5080。
- 不封顶：`LO_FPS=0`，日志里是 `native_target=0 host_cap=0`，游戏请求的 vsync 是 false。
- 着色器：`portable_dx12-613e43cab7fde729` 命中。管线语料 `pipelines_corpus-1766361aa92f292b`（3974 条）放在包旁边，和玩家自动下载时一样。所有测量窗口里新建的管线数都是 0。
- 原版定义：
  - 内部分辨率 720。
  - 抗锯齿、环境光遮蔽、各向异性过滤都关。
  - 阴影 1x，视锥剔除 100%。
  - 超分、帧生成、HDR 都关。
  - 景深 100、bloom、动态模糊、动态阴影保持开（这些是原版效果）。
  - FSR 锐化 0（RCAS 关，配置默认值）。
  - DLSS 模型用默认的 M。
- 场景：
  - Uhra 住宅区存档（`u3b_0_scrw`），角色原地站立。
  - 战斗：在同一处用 `LO_DEBUG_BATTLE_FILE` 开 formation 3，停在第一个指令。镜头对着 Kaim，约 270 个 draw，画面比 Uhra 轻得多。
- 采样：进场景（战斗是到第一个指令）后等 10 秒，取 10 秒窗口内每帧数值的中位数。
  - 帧间隔：`present timing frame_ms`。
  - GPU：`gpu_queue_batches_elapsed_ms`，只算渲染队列，不含 present 和合成器。
  - 渲染线程：`draw_ms`。
- 运行：每行一次，没有补跑。
  - 第一批（内部 720 基线）：Uhra 30 次，战斗 7 次，用时 31.7 分钟。
  - 第二批（内部 2160 基线）和 DLSS 5 神经渲染：Uhra 16 次，战斗 6 次，用时 19.3 分钟。
  - 另有 3 次本机试跑不计入结果。
- RTSS 在后台运行（只开了 OSD，全局限帧为 0），测试没有改动它。

## 怎么读

**Uhra 原版基线受 CPU 限制。** 帧间隔 6.78 ms（146.5 FPS），GPU 只有 2.33 ms，渲染线程 5.06 ms。帧间隔由 CPU 侧决定，不由 GPU 决定。

- 只增加 GPU 负担的选项，只要 GPU 时间仍低于约 6.8 ms，帧间隔 Δ 就接近 0。内部分辨率 2160 就是这样：GPU +3.27 ms，帧间隔只多 +0.02 ms。
- 所以主表同时给两种增量：
  - 帧间隔 Δ：这台机器、这个场景里玩家实际看到的变化。
  - GPU Δ：选项在 GPU 上多花的时间。在 GPU 受限的机器上（显卡较弱，或基线 GPU 时间已接近帧间隔），它会直接加到帧间隔上。
- 渲染线程 Δ 大的选项，即使在快显卡上也会拉长帧间隔。TAA、所有超分和三种帧生成都属于这类，渲染线程都多 1.8–2.2 ms，`record_ms` 从 1.45 ms 升到约 3.0 ms。
- 限制侧：
  - GPU：GPU 时间 ≥ 帧间隔的 85%。
  - CPU：GPU 时间低于帧间隔的 85%，只表示不是 GPU 受限。Uhra 里这些行的渲染线程 `draw_ms` 占帧间隔的 74–81%，没有一行达到 85%；战斗里约占 54%。
- 漂移：
  - Uhra 三次基线（开头、中间、结尾）分别是帧 6.75 / 6.79 / 6.80 ms，GPU 2.32 / 2.33 / 2.33 ms，渲染线程 5.05 / 5.07 / 5.07 ms，最大漂移 0.05 ms。
  - 战斗两次基线帧 2.22 / 2.20 ms。
  - 增量都相对基线平均值。0.1 ms 以内的差别和基线之间的差别同一量级。

## 超分

超分的输入尺寸由档位决定，与"内部分辨率"设置无关，日志已确认。每行给两种增量：

- 相对原版基线（内部 720，不开超分）。
- 相对同一输入尺寸、不开超分的运行，即超分本身的开销。

XeSS 的输入尺寸没有同尺寸对照，因为内部分辨率只能选 720/1080/1440/2160。表里给出它两边相邻的对照。

## DLSS 5 神经渲染（1 pass）

- dll：维护者提供的 `nvngx_dlssnr.dll`（165,840,496 字节），复制到测试目录 exe 旁边，只在下面两行使用。两行都放了这个 dll，只差 `dlss_neural_rendering`。
- 设置：超分 DLSS Quality（2560x1440 → 3840x2160），内部 720，其余为原版。NR 的预设、风格和强度等调节都用默认值。
- 日志确认 NR 在运行：
  - `DLSS NR: snippet initialized`
  - `DLSS NR: 1 feature(s) created for 3840x2160`
  - `DLSS NR: first evaluate recorded for 3840x2160, 1 pass(es)`

- DLSS Quality 不开 NR 的对照这次重测：帧 8.84 / GPU 7.82 / 渲染线程 7.10 ms。和第一批的 DLSS Quality 相差 +0.10 / +0.05 / +0.08 ms。

## 没测的项和原因

- MetalFX：只有 macOS 有。
- Vulkan 后端：两批都只测 D3D12。
- FSR FG 的输出帧率：SDK 计数为 0，日志里没有输出帧率。
- psvita（AMD Radeon 8060S，Proton D3D12）：改到本机之前只跑了一次启动试跑，没有进到场景，没有可用数据。
  - 原因：不封顶时按 swap 计数的按键在启动阶段就全部打出去了。
  - 日志在本机测试目录的 `psvita\` 下。

原始日志、每次运行的设置和截图在本机 `C:\Users\freefrank\worktrees\LostOdysseyRecomp\gfx-cost\runs\<标签>\`，每次运行一行的记录在同目录 `PERF_LOG.md`，测试脚本是同目录的 `gcw.py`、`batchw.py`（第一批）、`batchw2.py`（第二批）、`gcanw.py`，不随仓库分发。
