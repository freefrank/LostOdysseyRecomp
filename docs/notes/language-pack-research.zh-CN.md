# 语言包（#369）：导出、导入、新增语言的设计与可行性

2026-10-09。来源：静态阅读 main `ae84cf7e` 的代码和重编译 PPC；离线解析 Asia 版（int/jpn/kor/chi/sch）和 USA/Europe 版（int/jpn/deu/fra/spa/ita）光盘的 `LO.fpi`/`*.fpd`；一份已有的 debug 运行日志（Asia 盘 + 3 个 DLC，带 `NtReadFile` 行）。没有运行游戏。依据一栏：「代码」= 读代码确认，「离线」= 离线解析或原型验证，「日志」= 运行日志，「推断」= 未验证。

目标：modder 能把游戏文本导出成可编辑文件、翻译后导入游戏，并把译文作为新语言出现在设置里。第一个目标语言是巴西葡萄牙语。

## 结论

- 可行，游戏代码不用改。游戏按内存里的 `LO.fpi` 记录（偏移、存储长度、解码大小）读取归档成员。主机在 `LO.fpi` 被读入时改写目标记录，再给归档挂一段"虚拟尾部"，游戏就能读到任意长度的新内容。离线原型验证过：把 `menu_int.dat` 里 ID 9104 换成更长的葡语，补丁后的索引重新解析、按游戏的方式取回并解码，结果正确，其余记录不变。
- 文本合并放在运行时：导出和导入共用同一套 C++ 解析器，语言包只带译文，不带原文。装了 DLC 的玩家，部分文本文件实际生效的是 DLC 里的版本；运行时按 key 合并，对装没装 DLC 都成立，预先生成的二进制做不到。
- 底本用英语（INT）：两个版本都有，文件逐字节相同；INT 字体已经包含巴葡需要的全部字符。同一个巴葡包两个版本都能用，第一种新语言不需要补字形。
- 新语言不向游戏注册新的语言代码。游戏仍然认为当前是 INT，文本由语言包提供，设置里显示语言包的名字。
- 主要工作量在各文本格式的解析和重建。6 种格式已用 Python 原型做到"解析 → 不改内容重建"逐字节一致；`name_data.xmb` 和千年之梦（UE3 包内联文本）还需要逆向，放到后面。

## 1. 归档读取路径与叠加层

| 项 | 内容 | 依据 |
|---|---|---|
| 加载索引 | 启动时 `sub_82854400` 读 `LO.FPI`：先读 64 字节头，再一次读剩余部分（已用扇区数 ≤ 512，即 ≤ 1 MiB），之后常驻内存 | 代码、日志 |
| 记录 | 24 字节：`+8` 低 21 位为扇区号（字节偏移 = 扇区 × 2048，上限 4 GiB），高字节为盘号/层号；`+14` 的 `0x40` = CPX 压缩；`+16` 存储长度；`+20` CPX 解码大小 | 代码、离线（两版 4 盘全部记录核对） |
| 打开成员 | `sub_828551E8` 先查叠加索引（DLC），再查基础索引；`sub_828548A0` → `sub_82853B28` 按名字匹配并填写 file-info | 代码 |
| 读取 | OVERLAPPED 异步读，先读 0x20 字节探头，再整段或按 CPX 块分段读，偏移任意字节、不越出成员范围；没有"偏移不得超过 FPD 大小"的检查 | 代码、日志 |
| 主机侧 | `kernel/io/file_system.cpp` 的 `OpenFileHandle`、`NtReadFile`、`NtReadFileScatter`、`NtQueryInformationFile`；DLC 根 `XDC*:\` 也走 `OpenFileHandle` | 代码 |
| DLC | 3 个 DLC 覆盖 `namedata.bin`、`itemexplaindata.bin`、`dc*_scrw.jmd`（各语言），查找时排在基础索引之前；DLC 在约 9.4 s 挂载，而 `system.ini`、`coalesced.int`、`menu_int.dat`、名称和说明表在 6.0–7.4 s 已经读完 | 日志 |

**叠加层设计**（主机端，`file_system.cpp`）：

1. 游戏打开 `LO.FPI`（约 6.0 s）之前，加载语言包，算出 `{成员路径 → 新字节}`。
2. 打开 `lo.fpi` 或 `XDC*:\*.fpi` 时生成补丁后的索引镜像，`NtReadFile` 读 `[0, used)` 时从镜像取。每个被替换的记录：`+8` 保留高字节，低位改成尾部扇区号；`+16`、`+20` 填新值；`+14` 的 `0x40` 与载荷一致。
3. 新内容一律用 CPX 存储块（`0xFF`，不压缩）包装，不需要写压缩器。零售数据里本来就有大量这种块（disc1 有 13,048 个），游戏的解码器必然支持。
4. 虚拟尾部从 `RoundUp(真实大小, 2048)` 开始，每个载荷按 2048 对齐补零；读取落在尾部时从内存取；`NtQueryInformationFile` 报告扩展后的大小。尾部必须在 4 GiB 以内（最大的 `xenon_snd.fpd` 是 1.48 GB，余量充足）。
5. 每次打开 `LO.FPI` 都重新应用（换盘时也一样）。四张盘的 loc 成员内容相同、偏移不同，按盘分别补丁。

只靠"伪造一个 DLC 叠加包"不够：DLC 挂载太晚，启动期读取的文本覆盖不到。

这一层是通用的"按路径替换归档成员"，以后也能给其他用途使用（例如字幕重新定时、`AssetKind::File` 原样替换）。

## 2. 文本家族

规模按 disc1 的 int / jpn / deu 统计，"字符"不含控制码。

## 3. 语言选择与两个版本

| 项 | 内容 | 依据 |
|---|---|---|
| ID → 代码 | 主机通过 `XGetLanguage`/`ExGetXConfigSetting` 交出数字 ID；游戏启动时查 `loc/system.ini` 填出的注册表，得到 3 字母代码，写进 `GLanguage`（0x83238A28），只用这一次 | 代码 |
| 代码的用途 | 读 `GLanguage` 的 17 处全部是拼路径或包名（`loc/<code>/`、`_<code>` 包、`Coalesced.<code>`、`subtitle/<code>/`）；没有发现按数字 ID 或特定语言分支的逻辑 | 代码（范围内未发现，不等于证明不存在） |
| 文本与语音 | 分开：`TextFolders` 和 `SoundFolders`；游戏选项里的语音从 `SoundFolders` 选 | 代码 |
| 字幕 | 先找 `subtitle/<文本>/<语音>/`，没有就回退到 `subtitle/<文本>/`；INT 底本只需要 `subtitle/int/` | 代码 |
| Asia 版 | 文本 int/jpn/kor/chi/sch，语音 int/jpn/kor | 离线 |
| USA/Europe 版 | 文本 int/jpn/deu/fra/spa/ita，语音 int/jpn/deu/fra/ita（西语文本配英语语音） | 离线 |
| INT 跨版本 | `loc/int/` 568 个、`subtitle/int/` 752 个、`*_int.xxx` 244 个成员，文件数和长度全部相同，字体包字节相同 | 离线 |

两个版本都没有葡萄牙语。移植层把 ID 9 当作 SCH（沿用 exe 静态表的旧编号），而 Xbox 360 的 9 是葡萄牙语，所以**不能把 9 交给游戏当葡语**。

## 4. 字体

- 格式是 UE3 UFont：字符表（UV 矩形 + 页号）在包里存了两份，码位映射 `CharRemap` 是 u16→u16，没有逐字距调整；字形页是 DXT5、单 mip、LZO、Xenos tiling（离线）。
- INT 的 9 个通用字体（Maru23、Meiyo18、LocTit1 等）、3 个千年之梦字体（Maiandra）和 Title 都包含巴葡需要的 33 个字符（ã õ ç á à â é ê í ó ô ú ü 及大写、ª º “ ” « » – …），解码页面核对过字形完好（离线）。
- 缺口：片尾 StaffRoll 字体没有 `–`（用 `-` 代替）；引擎默认字体 Gothic11 没有重音字母，德法意西零售版同样如此，玩家可见文本应该不经过它（推断）。
- INT 和德法意西字体字符集相同（199 个），比 Latin-1 少 `¤¥¦§¬¯±µ¶·¸¼½¾Ð×Þð÷þÿ`，翻译时要避开。
- 移植层自己的设置菜单按 UI 语言读字体，不受游戏语言包影响。

以后要支持需要新字形的语言（波兰语、俄语等），推荐"主机加载时修补字体包"：语言包只带新增字形和度量，读取 `rpfonts*_<base>.xxx` 时在内存里扩充字符表、追加页面，用 `mod_api.h` 已预留的 Font 种类。估计 1–2 周，中等风险。只改像素或主机兜底渲染都不推荐。

## 5. 语言包格式（提议）

导出：

```text
LostOdysseyRecomp.exe --export-assets <dir> --export-kinds text
<dir>/text/<lang>/<成员路径>.json      {"<key>": "<原文>"}，UTF-8
<dir>/text/index.csv                    成员路径、语言、来源（基础或某个 DLC）、条数
```

语言包（mod 文件夹，MO2 和手动安装都适用）：

```text
mods/<id>/language.ini                  id=pt-BR, name=Português (Brasil), base=int
mods/<id>/text/<成员路径>.json           {"<key>": "<译文>"}，只放翻译过的条目
```

- 有 `language.ini`：新增一种可选语言，基于 `base`。
- 没有 `language.ini`：覆盖同名语言的文本（例如修正英文错字）。
- 缺的 key 回退到原文；多出来的 key 记一条警告。
- 作者工具 `lo_mod.py language-check`：对照导出检查 key、控制码记号是否成对、每个字符是否在底本字体的 `CharRemap` 里。

设置：`settings.ini` 保留 `game_language=<base 的 ID>`，新增文本键 `game_language_pack=<id>`。语言列表改成运行时生成，在 `ConfigureGameLanguages` 里追加 base 存在于当前版本的语言包（mod 初始化早于这一步）。还要改 `restart::Required`、设置菜单、首次运行向导；`quit_text_hook` 对 9104/9114/9120 要让位给语言包的译文。

## 7. 需要拍板的事（附建议）

1. 底本：INT。理由见上，两个版本通用、字体齐全。
2. 合并位置：运行时（导出和导入共用 C++ 解析器，语言包只带译文）。
3. 新语言：不注册新的游戏语言代码，游戏仍看到 base。
4. 字体补字：推迟，巴葡不需要。
5. 千年之梦和 `name_data`：放 P3，但语言包目录结构现在就预留这两类。

## 8. 风险与未决问题

- 更长的文本会不会碰到固定大小的缓冲或内存池（游戏按 `+20` 的解码大小分配，没有发现固定池，但没有实测）。这是唯一可能推翻整个方案的问题，P1 第一件事就是测它。
- 自动折行在哪里实现还没找到；葡语比英语长 20–30%，固定宽度的菜单框可能溢出，译者要用 `{E001}` 等手动换行。
- 游戏遇到字体里没有的字怎么显示（占位方块还是跳过）未确认，`language-check` 先在导入前拦住。
- 多个 DLC 覆盖同一路径时的先后顺序；导出要记录每个成员来自基础还是哪个 DLC。
- JMD 控制码的确切语义是根据参数分布推测的；导出原样保留记号，不需要懂语义。
- 选日语语音时，INT 文本的字幕沿用按英语配音计时的版本（零售英文版本来就这样）。语言包想为日语语音单独定时，需要叠加层支持新增成员，不在 v1 范围。

原型脚本（Python，不进仓库）：FPI/FPD/CPX 读取、叠加层原型、`DAT$`/字符串库/JMD/Coalesced 解析与重建、`xmlbin` 字符串池、字体字符表与覆盖统计。它们作为 P0 C++ 实现的对照。
