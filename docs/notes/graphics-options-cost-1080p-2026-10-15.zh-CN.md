# 画质选项的开销（1080p 输出）：main f7799aec，RTX 5080 与 psvita，2026-10-15

本记录给出 1920x1080 输出下每个画质选项相对"原版"设置多出的毫秒数，测两台机器：RTX 5080 台式机和 psvita（Strix Halo 核显）。每行只改一个设置，其余保持原版。方法与 [4K 报告（2026-10-10）](graphics-options-cost-2026-10-10.zh-CN.md)相同。测试在 2026-10-14 晚（本地时间）进行。

## 条件

### 两台机器相同的部分

- 版本：origin/main `f7799aec`（源码版本 0.9.52）。
  - 用 `tools/build_worktree.bat` 构建 windows-clang 产品配置，编入 DLSS、Streamline（DLSS-G）、FSR 3.1（含 FG）和 XeSS 3.0.2（含 XeSS FG）。
  - 两台机器跑同一个 exe。各行日志里分别有 `DLSS SR feature created`、`FSR recorded`、`XeSS: ready`、`DLSS NR: … pass(es)` 和 `D3D12 FG: … active=true`，说明这些功能都编进去了，并且在对应的行里确实在运行。
- 着色器：
  - 本构建的合同是 D3D12 `05fd9431…`、Vulkan `03ef0787…`，和 `shader-packs` 发布页 2026-10-12 的两个包一致。
  - 所以直接用发布包 `portable_dx12-05fd9431d3febc7b` 和 `portable_vk-03ef078715ed8c8b`，旁边放管线语料 `pipelines_corpus-183df2d935260e33`（3974 条）。
  - 每次运行的日志都有 `portable shader pack hit`。表里所有测量窗口新建管线数都是 0。
- 输出：1920x1080 窗口（`window_mode=0`），日志 `swapchain=1920x1080`。
- 不封顶：`LO_FPS=0`，日志 `native_target=0 host_cap=0`、`requested_vsync=false`。
- 原版定义：
  - 内部分辨率 720。
  - 抗锯齿、环境光遮蔽、各向异性过滤都关。
  - 阴影 1x，视锥剔除 100%，动态阴影开。
  - 景深 100、bloom、动态模糊开（这些是原版效果）。
  - 缩放滤镜"高"（默认值）。
  - 超分、DLSS 5 神经渲染、帧生成、HDR、性能信息都关。
  - 垂直同步关，FreeSync / G-SYNC 关。
  - FSR 锐化 0，DLSS 模型 M。
- 场景：
  - Uhra 住宅区存档（`u3b_0_scrw`），角色原地站立，约 2140 个 draw。
  - 战斗：在同一处用 `LO_DEBUG_BATTLE_FILE` 开 formation 3，停在第一个指令。镜头对着 Kaim，约 260 个 draw，画面比 Uhra 轻得多。
- 采样：进场景（战斗是到第一个指令）后等 10 秒，取 10 秒窗口内每帧数值的中位数。
  - 帧间隔：`present timing frame_ms`。
  - GPU：`gpu_queue_batches_elapsed_ms`。只算渲染队列的提交批次，不含 present 和合成器，也不含 SDK 生成帧的工作。
  - 渲染线程：`draw_ms`。

### psvita

- AMD Ryzen AI Max+ 395，Radeon 8060S 核显（RADV，Mesa 26.2.2），Bazzite 44（内核 7.2.4），2560x1600 120 Hz 屏。
- 同一个 Windows exe 通过 umu-run + GE-Proton10-34 运行。D3D12 走 vkd3d-proton，Vulkan 走 winevulkan。1920x1080 可见窗口，日志 `swapchain=1920x1080`。

  - 背靠背运行时，每次结束都到 95 °C 左右，测量窗口里常有几秒的 90–100 ms 卡顿，中位数也变慢。

## 怎么读

**RTX 5080 的 Uhra 基线不是 GPU 受限。** 帧间隔 4.90 ms（201 FPS），GPU 2.29 ms，渲染线程 3.22 ms。帧间隔由 CPU 侧（游戏线程、渲染线程、present）决定。

- 只增加 GPU 负担的选项，只要 GPU 时间还低于约 4.2 ms，帧间隔 Δ 就接近 0。内部分辨率 1440 就是这样：GPU +0.96 ms，帧间隔不变。
- 所以表里同时给两种增量：
  - 帧间隔 Δ：这台机器、这个场景里玩家实际看到的变化。
  - GPU Δ：选项在 GPU 上多花的时间。在 GPU 受限的机器上（例如 psvita 的战斗），它会直接加到帧间隔上。
- 渲染线程 Δ 大的选项，即使在快显卡上也会拉长帧间隔。TAA、所有超分和所有帧生成都属于这类。
- 限制侧：
  - GPU：GPU 时间 ≥ 帧间隔的 85%。
  - CPU：GPU 时间低于帧间隔的 85%，只表示不是 GPU 受限。
- 噪声：
  - RTX 5080 Uhra 四次基线是 5.00 / 4.85 / 4.89 / 4.85 ms，相差 0.15 ms。单次运行偶尔会整体慢一截（DLSS Performance 第一次 9.02 ms，复测 6.03 ms），0.15 ms 以内的差别当作噪声。
  - psvita 的 CPU 侧噪声大得多：同一设置的基线，帧间隔在 11.2–15.2 ms 之间，Vulkan 基线的渲染线程在 11.8–12.6 ms，同组里有一行快到 8.1 ms。psvita 上帧间隔 Δ 和渲染线程 Δ 只有明显超过这个范围才算数；GPU Δ 稳定得多，以它为准。

## 值得注意的发现

- **1080p 下 RTX 5080 只在 DLSS 5 NR 时 GPU 受限。** 原版基线 4.90 ms（201 FPS）由 CPU 侧决定。内部分辨率 1440、阴影 4x、AO、AF 这些只加 GPU 的选项，帧间隔都不变。
- **TAA、所有超分和帧生成的代价在渲染线程上，约 1 ms。** TAA +1.14 ms，超分各档 +1.0–1.3 ms，DLSS-G +0.7–0.8 ms，XeSS FG +1.3 ms。档位和输入尺寸只影响 GPU。4K 报告（v0.9.22）里 TAA 的渲染线程开销是 +1.83 ms、超分是 +1.9–2.2 ms，渲染线程的开销和输出分辨率无关，所以这是 main 相对 v0.9.22 的变化，这里没有查是哪个提交带来的。
- **FSR FG 最贵。** RTX 5080 上 +3.96 ms（渲染线程 +2.48 ms），比 DLSS-G 和 XeSS FG 高得多；SDK 计数一直是 0，看不到它的输出帧率。psvita 上也是 0。
- **DLSS-G 的倍数几乎不影响代价。** 2x / 3x / 4x 的帧间隔 Δ 是 +0.69 / +0.73 / +0.81 ms，SDK 计数的输出是渲染帧率的 2 / 3 / 4 倍。
- **动态阴影关和视锥剔除 200% 是两个能省 CPU 的选项。** 动态阴影关 -0.64 ms（draw 少约 270 个），剔除 200% -0.32 ms（draw 少约 160 个）；剔除 0% 多 +0.42 ms。
- **DLSS 5 NR 每个 pass 在 1080p 约 4.3–4.8 ms GPU。** 1 pass 就让 RTX 5080 变成 GPU 受限（123 FPS），4 pass 47 FPS。
- **psvita 在 1080p 输出、内部 720 时仍是渲染线程受限。** Uhra 约 75–85 FPS，GPU 只有 4–6 ms。GPU 开销大的选项在 psvita 上很明显：
  - 内部 1440 让 GPU 涨到约 24 ms（约 40 FPS），是最贵的单项。
  - 阴影 4x GPU +4.3–4.7 ms，在 RTX 5080 上只有 +0.42 ms。
  - XeSS Native AA GPU +8.3 ms，FSR Native AA +4.0 ms。
  - 战斗场景在 psvita 上是 GPU 受限，GTAO +1.3 ms、TAA +1.0 ms、阴影 4x +1.0 ms 会直接体现在帧间隔上。
- **Vulkan 的 GPU 计时数字比 D3D12 小一半。** 两个后端用同一种计时（每个提交批次首尾写 timestamp，plume 的 Vulkan 用 `BOTTOM_OF_PIPE`，D3D12 用 `EndQuery`），但批次划分和驱动排队不同。这个差别没有核实，不要把它读成"Vulkan 的 GPU 工作少一半"。帧间隔上 Vulkan 比 D3D12 快 0.26 ms，在噪声边缘。
- **psvita 背靠背测试会撞上温度墙。** 每次运行都升到 95 °C，测量窗口里出现几秒 90–100 ms 的卡顿。每次运行前等到 84 °C 以下后，窗口干净多了。以后 psvita 的性能测试应该默认加这个冷却。

## 没测的项和原因

- 本次收尾时停掉、没有跑的：
  - FSR FG 的复测（RTX 5080），以及 DLSS Performance、模型 L、SSAO 的第二次复测。这三行表里用的是一次复测的值。
  - psvita 的内部 1440 基线两组（Uhra、战斗）和内部 1080 战斗组。1080 战斗组只跑了预热和一次基线。
  - psvita 冷却后的 Uhra 720 全组重测。表里那组大部分是冷却前的数据。
- psvita 上的 DLSS、DLSS 5 NR、DLSS-G：需要 NVIDIA 显卡。
- psvita 上的 HDR：Proton 下 `display_active=false`，没有可测的 HDR 输出。
- 垂直同步和 FreeSync / G-SYNC 的实际效果：`LO_FPS=0` 下它们不生效；要测它们得用封顶运行，不在本报告的方法里。
- MetalFX：只有 macOS 有。
- 本机 Vulkan 只测了基线一行；FSR 的 Vulkan 行只在 psvita 上测了。
