# v0.5.0 性能诊断记录

2026-09-09。对象是 source 0.5.6、Ryzen 7 9800X3D + RTX 5080、Map16 固定视角、internal 2160、TAA3、cap60、4K 输出。本文记录性能原因证据，不代表新优化、用户验收或稳定 60 FPS。

## 运行测量

同一 EXE 的内部记录为 20 秒、961 帧，mean accepted-present interval 20.8071 ms，p95 22.8661 ms，p99 26.0708 ms，48.0606 accepted presents/s。RTSS 在保持窗口可见、但不激活和置底的条件下，独立窗口为 18.391 秒、18 个完整统计窗口内的 883 次 Present、48.0126 FPS；观测 frame time 均值 20.8115 ms，p95 22.890 ms，p99 26.075 ms。RTSS 读取的是拦截 Present 统计，不是物理 scanout。

此前 RTSS 全零的原因已确定：隐藏窗口会触发 RTSS hook 的 `IsWindowVisible` 过滤。仅添加 `WS_VISIBLE`，并保持 `SW_SHOWNOACTIVATE`、`HWND_BOTTOM`、`SWP_NOACTIVATE` 和不抢前台，便恢复了 D3D12 数据。没有修改 RTSS profile、权限、OSD 或 hook binary。

## CPU 采样与提交路径

20 秒 profiler 目标 PID 16836，creation FILETIME `134334453492422398`，采样到 1,789 条有效 RIP，采样窗口 20.0052 秒。renderer/command thread 69900 的 bounding CPU 为单逻辑核约 57.62%；448 个样本中 114 个直接处于 `NtWaitForSingleObject`，其中 88 个调用栈到达 `Renderer::Flush`。这支持渲染 flush 中存在反复等待，但不等于全机 CPU 饱和或 GPU 饱和。

该线程还出现 50 个 GetShader 与 pipeline-key FNV 路径样本、30 个 `SampleHash` 样本和 26 个 index conversion 样本。报告中的 wall 样本比例不是 CPU 百分比、不是可直接回收的毫秒数，也不能直接推导 FPS 收益。每个 GPU batch 当前 execute 与 wait 串行；descriptor 的 500 是应用层 batch 预算，不是硬件上限。

## 结论和限制

本轮没有实施新的性能优化，也没有追加功能测试、版本递增或发布。常量读取的直接 A/B 结果仍是 4.147→0.576 ms，但内部 legacy/bulk 与外部 CPU/NVML 采集窗口存在长度和背景负载/boost 差异，不能把全部 accepted-present 差异归因于该改动。1080 测得 57.14 accepted/s，但测窗前输出已变为 3840×2054，故仅为探索性结果，不作为严格分辨率 A/B。进一步 4K 优化、Vulkan DPI144、fullscreen/Alt+Enter 和用户验收仍待完成。

## 后续直接修复 — source 0.5.7

用户要求停止追加诊断并停用 subagent 后，主代理直接修复了重复 shader FNV 热点：复用命令处理器的 word hash 作为索引，完整比对微码内容后缓存 renderer byte hash，供 shader 与 pipeline 查询共用。同地址内容改变及 hash 索引碰撞仍会校验，CPU 缓存设有容量边界。74 项定向检查通过，修复候选完成一次 20 秒 Map16 对照。

保持 D3D12、TAA3、60 FPS cap 和 3840×2160 内部/输出，同一存档固定视角：内部帧间隔 20.8071→18.5178 ms，48.0606→54.0022 accepted presents/s；RTSS 48.0126→54.0511 FPS（观察提升 12.6%），p95 22.890→19.995 ms。绘制 wall time 13.0326→10.7875 ms，GPU 批次 4.8042→4.7204 ms。新窗口 1080 连续帧，无新增 shader/pipeline/texture、capture 或 trace；截图场景正常。系统背景 CPU 和 GPU boost 略有差异，这是限定条件下的观察结果，尚未达到稳定 4K60。

验证后版本递增到 0.5.7，四个版本消费者重编并链接，未重复游戏/测试。游戏正常关闭，存档、profile 和任务配置未变。尚未 commit/push/release；完整结果与可执行文件见 `out/v0.5.0/performance-fix/REPORT.md`。后续热点仍包括 vertex/index 准备与按批次同步等待，用户验收待完成。

## 当前 0.5.0：几何准备与限帧等待修复

根据用户最新要求，源码和发布目标统一恢复到 **0.5.0**，不再按功能递增；AGENTS.md 已同步。旧 0.5.6/0.5.7 文件名仅保留为历史产物证据。本轮未使用 subagent。

顶点缓存改为精确比较原有采样范围内的字节，索引／图元转换复用临时数组并将宽度、字节序判断移至循环外。内容变化仍分配新 GPU 区间，不覆盖在用资源。针对实测普通休眠的唤醒超时，限帧改用可复用的高精度等待定时器；原有 FramePacer 规则不变，不采用忙等。几何值／边界检查以及高精度、普通定时器两种模式的截止时间检查通过。

固定 Map16、D3D12、TAA3、内部和输出均 3840×2160：RTSS **54.05→58.33→59.76 FPS**；最终内部平均 **59.79 FPS / 16.72 ms**，p95 **17.16 ms**。相对 shader-only 基线，顶点准备 **1.57→0.65 ms**，索引准备 **1.93→0.29 ms**；几何版至最终版的平均唤醒超时约 **0.65→0.28 ms**。最终窗口 1196 连续有效帧，截图场景正常，窗口/DPI 不变、未抢前台，无新增 shader/pipeline/texture 或测窗内 capture/trace。系统 CPU、GPU 频率及采集器开销不同，属于限定实景的观察改善，不能代表全游戏稳定 60 FPS。
